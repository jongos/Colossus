# Exact-plan cleanup (CLI v0.9.0)

This is permanent deletion with no undo. Only explicitly selected regular files on local Windows NTFS are supported: 1–64 targets, 256 MiB per file, 1 GiB per plan. Repository/worktree ancestry, retention-registry ancestry, managed cache/environment paths, source/configuration extensions, hard links, reparse/cloud files, cross-volume traversal and directories are refused. Unsupported cases need a future native adapter; do not replace refusals with shell deletion.

1. Establish ownership, current-use, retention and recovery evidence for every exact target. Names, size, age, duplicates and extension eligibility do not establish disposability. Unresolved concerns remain holds.
2. Check `colossus --version`. Choose an explicit root and exact absolute target files. Create an unused plan path outside that root; its parent must exist. Run `colossus cleanup plan --root ABSOLUTE_ROOT --file ABSOLUTE_FILE --reason REVIEW_REASON --recovery RECOVERY_CONSEQUENCES --output ABSOLUTE_NEW_PLAN`, repeating `--file` for each target.
3. Run `colossus cleanup review --plan ABSOLUTE_PLAN`. Present all target paths, identities, hashes, logical/allocation sizes, permanent-deletion consequences, preserved files and plan digest to the user. Obtain explicit approval for this exact plan before invoking execution. Approval to investigate or implement cleanup is not deletion approval. Changed targets require a new plan and approval.
4. Run `colossus cleanup execute --plan ABSOLUTE_PLAN --receipt ABSOLUTE_NEW_RECEIPT` in an interactive terminal. The receipt parent must exist outside the cleanup root. After exact user approval, enter the displayed `DELETE sha256:...` phrase for that plan, or let the user enter it. Piped input is refused. If no interactive terminal is available, stop before execution; do not bypass the terminal guard or invoke the library/test harness.
5. Verify the receipt's matching plan, intents/outcomes, final `complete` status and target absence; verify preserved controls/recovery material separately. Report confirmed removed-file allocation and before/after free-space observations separately. Free-space delta includes concurrent activity and journal growth; `causal_reclaimed_bytes` remains unknown.

Execution preflights every target using exclusive handles, pinned ancestry and hashes before approval. Stale or unsupported entries stop the operation. Cancellation stops before the next target, but completed deletion cannot be undone. A journal lacking `finished`, a failed operation or an unconfirmed outcome is incomplete. Never automatically retry an approved plan or delete a replacement path; reconcile the receipt and request fresh approval if another action is needed.

The successful synthetic test is ignored by default and also requires exact human approval. Do not run `cargo test -- --include-ignored` indiscriminately. The approval files and environment variables in CI are test infrastructure only, never a production authorization shortcut. No system/personal-media cleanup or automatic deletion schedules are supported.

For CLI v0.10.0 or later, `colossus cleanup receipt --receipt ABSOLUTE_RECEIPT` provides read-only JSON diagnostics for one explicitly selected journal. It does not open referenced targets. Exit 0 means internally consistent completion claims, 2 means partial/interrupted claims, and 1 means invalid or unreadable input. A final incomplete line or unresolved intent requires manual reconciliation; deletion may already have occurred. Receipt consistency never proves approval or current filesystem state and never authorizes retry. Check the installed version; v0.9.0 does not have this command.
