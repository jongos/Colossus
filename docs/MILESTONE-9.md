# Milestone 9: approved file deletion — implementation in progress

**Development branch published; compilation, 17 non-deleting tests and strict lint passed on Windows CI. Successful deletion remains unvalidated. Not installed or released. No deletion has run.** Local Windows Smart App Control rejects the existing unsigned Rust compiler (Code Integrity events 3077/3033). No security settings or policy were changed. This is an operating-system block, not an agent approval rejection.

## Source implemented

- Separate strict cleanup-plan schema; ordinary audit reports and portable survey checkpoints are not executable.
- `cleanup plan --root ABSOLUTE_ROOT --file ABSOLUTE_FILE [--file ...] --reason REVIEW_REASON --recovery RECOVERY_CONSEQUENCES --output ABSOLUTE_NEW_PLAN`.
- `cleanup review --plan ABSOLUTE_PLAN` displays the exact target paths, identities, hashes, sizes, reason and recovery consequences.
- `cleanup execute --plan ABSOLUTE_PLAN --receipt ABSOLUTE_NEW_RECEIPT` requires a terminal and the affirmative phrase `DELETE <exact plan digest>` after displaying the plan. Piped input, blanket approval options and checkpoint-based approval are not supported.
- Full target-set preflight before approval/mutation, pinned ancestry, exclusive file handles, SHA256 comparisons, single-link and allocation requirements, local NTFS checks and per-operation rechecks.
- Handle-based Windows delete disposition instead of recursive shell deletion. No new targets are discovered during execution.
- Durable JSONL intent/outcome journal outside the cleanup root. Cancellation stops before the next operation; failures stop the remaining set. A journal without `finished` is interrupted/incomplete, never success. There is no automatic replay or undo.
- Before/after volume free-space observations and confirmed removed-file allocation. Observed free-space change is not claimed as causal reclaimed space.

## Deliberately restricted first scope

Exact regular files only: 1–64 targets, at most 256 MiB per file and 1 GiB per plan. No directory removal, hard links, reparse/cloud-placeholder files, cross-volume traversal, source/configuration extensions, managed cache/environment paths, repositories/worktrees or ancestry containing a retention registry. Supported artifact extensions are only an input restriction, never evidence that a file is disposable. Users must review ownership, active use, retention and recovery before approval; the executor does not prove those facts.

Repository/worktree and retention checks are conservative refusals, not partial adapters. Reclaiming arbitrary build trees inside repositories, package caches, directory removal, quarantine/restoration and native package-manager/Git lifecycle handling remain future work. This first implementation must not be presented as full workspace cleanup support.

## Tests prepared

`tests/cleanup_refusal.rs` contains 17 non-deleting tests for plan preservation, denial, stale/tampered targets, prohibited scope, hard links, whole-set preflight, cancellation, control-output boundaries, plan serialization and piped-approval refusal. Fixtures are retained; no successful delete is invoked by these tests.

`tests/cleanup_approved.rs` contains one ignored successful-deletion test, which must only be invoked after a human approves the exact pre-created plan and digest. It removes exactly `delete-a.bin` and `delete-b.bin` in the dedicated synthetic root, preserves `preserve.bin`, verifies the journal/storage observations and checks that stale replay is refused. Its test-only environment values identify the already approved plan; they are not an application approval mechanism.

Two 4 MiB synthetic files and a preservation control have been created under this task's `work/colossus-approved-synthetic-20261025/targets`. They have NOT been approved for deletion and remain intact. The native plan/digest must be generated by the compiled planner before requesting approval. Do not run a blanket `cargo test -- --include-ignored`: the successful-deletion test requires separate approval.

With explicit user authorization, the draft was published to `dev/approved-cleanup`. [Windows CI run 40228968472](https://github.com/jongos/Colossus/actions/runs/40228968472) passed all 17 refusal tests, `cargo clippy --all-targets --locked -- -D warnings`, and compilation of the ignored successful-deletion test without running it. The runner used Rust/Cargo 1.99.1 on Windows 2025. The first run exposed an incorrect assertion about escaped Windows path display; that assertion was corrected. CI now checks committed formatting rather than formatting before tests. No full audit regression suite or successful-deletion test was executed in this milestone.
